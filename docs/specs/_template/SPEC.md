# Spec Template

> 新功能/重构的规格文档模板。放在 `docs/specs/{feature}/` 目录，包含以下文件。

## 目录结构

```
docs/specs/{feature}/
├── SPEC.md          # 功能规格（必填）
├── API.md           # API 契约（涉及 API 时必填）
├── DATABASE.md      # 数据库变更（涉及 DB 时必填）
├── ARCHITECTURE.md  # 架构设计（涉及架构变更时必填）
└── TEST.md          # 测试计划（可选）
```

## SPEC.md 模板

```markdown
# {功能名称} 规格

## 1. 背景与目标

### 背景
（为什么需要这个功能）

### 目标
- 目标 1
- 目标 2

## 2. 功能范围

### 包含
- 场景 A
- 场景 B

### 不包含
- 场景 X（后续版本考虑）

## 3. 用户故事

### 故事 1：{标题}
- **作为** {角色}
- **我想要** {功能}
- **以便** {价值}

**验收标准：**
- [ ] 标准 1
- [ ] 标准 2

## 4. 功能描述

### 4.1 {子功能 A}
（详细描述）

### 4.2 {子功能 B}
（详细描述）

## 5. 权限需求

| 角色 | 权限码 | 允许操作 |
|------|--------|----------|
| 管理员 | `xxx:read` | 读 |
| 管理员 | `xxx:write` | 写 |

## 6. 依赖

- 依赖功能 A（`docs/specs/feature-a/`）
- 依赖服务 B

## 7. 非功能需求

- 性能：列表查询 < 200ms（1000 条数据）
- 安全：需要登录，管理员角色
- 可用性：接口可用性 ≥ 99.9%

## 8. 里程碑

- [ ] M1: 基础 CRUD（日期）
- [ ] M2: 完整功能（日期）
- [ ] M3: 测试完成（日期）

## 9. 参考资料

- 相关 issue：#123
- 外部 API 文档：...
```
