# 兼容代码清理计划

## 决策锚点（用户已拍板）

| 决策 | 方案 |
|---|---|
| delFlag | 统一为 `Boolean`（`delFlag Boolean @default(false)`） |
| DB provider | 保持 PostgreSQL，不动 migration_lock |
| BigInt 主键 | 本次不动，仅收敛全仓序列化写法（统一 `String(id)`），Int 降级留独立 PR |
| 种子数据 | 保留种子文件，重写结构 |

## 执行计划（9 步）

### Step 1 — Prisma Schema：delFlag → Boolean

**文件**：`apps/server/prisma/schema.prisma`

所有 20+ 张表中的：
```
delFlag String @default("0") @map("del_flag") @db.Char(1)
```
统一改为：
```
deleted Boolean @default(false) @map("deleted")
```

**影响**：所有 migration 文件中 `delFlag` 列的引用需要适配。

> ⚠️ 这一步会生成新的 Prisma Migration，文件名如 `YYYYMMDDHHMMSS_rename_del_flag_to_deleted`。

## 风险评估

| 步骤 | 风险 | 缓解 |
|---|---|---|
| Step 1 delFlag 迁移 | 高：20+ 张表字段改名，migration 重写 | 先备份 DB，migration 单独 commit |
| Step 2 seed 重写 | 中：menuId 重新编号，关联的 fixture 也要改 | fixture 同步改，一步提交 |
| Step 5 deviceType | 低：删除字符串兜底，前端已有 enum | 验证登录/在线设备端到端 |
| Step 8 前端类型 | 中：修改 api-gen 文件，生成器会覆盖 | 先跑 `gen-api` 再手动改 |
